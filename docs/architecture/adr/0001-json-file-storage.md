# ADR-0001: JSON-файли як сховище

- **Номер:** 0001
- **Статус:** Прийнято. Рішення діє з `fcb49bf` (2026-09-13); ADR записано ретроспективно 2026-11-27.
- **Компонент:** [SDD: Сховище](../../sdd.md#sdd-storage), [ISD: сховище і бекап](../../isd.md#isd-storage)

## Контекст

Перша версія (коміт `fcb49bf`, «Baseline: task manager CLI») була CLI для однієї людини. Задачі зберігалися в `tasks.json` через `TaskStorage`. У Лабі 4 (`7bcab9e`, `a66f1d6`) додано такі файли:
- `users.json` і `consents.json` через `JsonStorage`;
- `save_all` для анонімізації, яка змінює два файли одночасно.

Вимоги:
- нуль зовнішньої інфраструктури;
- дані читаються очима і легко створюються для тестів (`tmp_path`).

## Розглянуті альтернативи

| Варіант | За | Проти |
|---|---|---|
| **JSON-файли (обрано)** | stdlib, нуль залежностей, файл видно і легко створити у фікстурі | читання і запис усього файлу на кожен запит, немає блокувань і транзакцій між файлами |
| SQLite (`sqlite3` у stdlib) | транзакції, індекси, теж без сервера | схема і міграції, складніше дивитися дані і створювати їх у тестах |
| PostgreSQL | конкурентний доступ, бекапи, масштаб | окремий сервіс, Docker у dev і CI, мережеві секрети |
| Лише пам'ять | найпростіше | дані зникають після перезапуску |

## Рішення

Зберігати сутності в окремих JSON-файлах, шляхи до яких задаються через `TASKS_DB`, `USERS_DB` і `CONSENTS_DB`. Запис кількох файлів іде через `save_all`:
1. серіалізація всіх файлів у `*.tmp`;
2. `os.replace` для кожного файлу.

Помилка серіалізації не змінює жодного файлу.

## Наслідки

- **Плюси:**
  - нуль інфраструктури;
  - тести ізольовані через `tmp_path` (118 тестів проходять за 0.73 с);
  - відновлення копіюванням файлів зайняло 0.39 с (`docs/audit/restore_drill.txt`).
- **Мінуси:**
  - `GET /tasks` читає весь файл. Лаба 5 (коміти `1cbb321`, `62cc6f7`): на 5000 задачах безпечний максимум 60 RPS, обвал на 70 RPS, а під soak-навантаженням 45 RPS метастабільний колапс на 2.5 хв.
  - Немає блокування файлів: кілька воркерів uvicorn можуть перезаписати зміни один одного.
  - `os.replace` атомарний для кожного файлу окремо, а не для групи файлів (див. коментар `ponytail:` у `user_storage.py`).
- **Коли переглянути:** при появі prod-середовища, кількох воркерів, або якщо потрібен RPS понад 60. Шлях міграції – SQLite за тим самим інтерфейсом `load/save` (порти `TaskStore` і `ConsentStore` у `task_ports.py`).
