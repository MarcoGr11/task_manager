# Change Control Board: регламент і протоколи

<a id="rules"></a>

## Регламент

| Пункт | Правило |
|---|---|
| Склад | архітектор, QA, SRE, продуктовий власник (PO). У навчальному проєкті всі ролі виконує MarcoGr11; реальних осіб потребує підтвердження студента |
| Кворум | 3 з 4 членів; обов'язково присутній SRE для змін, що впливають на експлуатацію (runtime-код, дані, алерти) |
| Засідання | щочетверга о 10:00 UTC; позачергове засідання за SEV1, SEV2 або протермінованою CAPA |
| Подання RFC | не пізніше ніж за 2 робочі дні до засідання; RFC має містити Impact Analysis на 7 рівнів і план відкату |
| Рішення | Approved, Approved з умовами, Rejected або Deferred; простою більшістю. Голос SRE або QA «проти» з причини ризику даних означає вето до усунення |
| Підстави для Rejected | немає плану відкату; Risk Exposure High без пом'якшення; зміна суперечить [[slo#policy]] під час freeze; немає тестів на зміну поведінки |
| Standard-зміни | попередньо схвалені, без засідання: зміни лише документації з зеленим CI `docs.yml`; патчі залежностей із зеленими тестами |
| Emergency-зміни | ECAB: SRE + будь-який ще 1 член, рішення ≤ 1 год, ретроспективний розгляд на найближчому засіданні |
| Change freeze | (1) вичерпано error budget SLI, якого стосується зміна; (2) SEV1 за останні 7 днів; (3) календарний freeze 23.12–07.01. У freeze дозволено лише Emergency-зміни через ECAB і зміни, що підвищують надійність того SLI, бюджет якого вичерпано |
| Протокол | кожне засідання фіксується тут: склад, кворум, аргументи, рішення, умови |
