# IA-001: Impact Analysis для RFC-001

Аналіз виконано до реалізації (стан Assessment). У стовпці «Факт» звірено з `git diff --stat` коміту реалізації (`doc/lab12_results/ia_actual_diff.txt`).

## 1. Вимоги

| Вимога | Вплив |
|---|---|
| SLI `background_notifications` ≥ 99% ([[slo]]) | **нова властивість**: недоставлена нотифікація не губиться, її можна доставити повторно; SLI вимірюється метрикою, а не логом |
| Нефункціональна: `POST /tasks` не падає через нотифікатор (ADR-0002) | зберігається: fallback, як і раніше, повертає 201 |
| Нова операційна вимога | відмова залежності виявляється за ≤ 2 хв (`NotifierFallbackRatio`) |

## 2. Архітектура

- Новий компонент: файловий outbox (`tasks/notifier_outbox.py`) і ручна команда replay. Асинхронного воркера немає, він винесений у TD-A1.
- Нове рішення [[architecture/adr/0005-notification-outbox|ADR-0005]]. ADR-0002 переходить у статус Superseded у частині «нотифікацію буде втрачено». Retry і backoff лишаються чинними.
- Нових мережевих залежностей і процесів немає.

## 4. API

Порівняння з `docs/api/openapi.yaml` (версія 1.0.1):

| Елемент | Зміна | Клас |
|---|---|---|
| `POST /tasks`: тіло, коди, схема `TaskCreated` | без змін; `notification_delivered=false` тепер означає «відкладено в outbox», а не «втрачено» | семантика, **additive** |
| `GET /metrics` | нові серії `notifier_delivery_total{result}` | **additive** |
| Інші маршрути | без змін | – |

Breaking-змін немає, тож `info.version` OpenAPI не змінюється. Версія релізу застосунку: `1.1.0` (MINOR, додано функціональність).

## 5. Дані

- **Новий файл.** `NOTIFIER_OUTBOX`, формат JSON Lines: один рядок на одну `Task.to_dict()`. Створюється при першому fallback.
- **Міграції.** Немає: наявні `tasks.json`, `users.json`, `consents.json` не змінюються.
- **Бекап.** Outbox додається до сховищ `scripts/backup.py` і до backup policy, бо записи outbox – це дані, які ще не доставлено.
- **Персональні дані.** Задача містить `owner_id`, але не PII. Outbox не розширює PII-периметр ЛР4.

## Risk Exposure

Ймовірність (P) і наслідки (I) оцінено за шкалою 1–5. RE = P × I.

| Ризик | P | I | RE | Пом'якшення |
|---|---|---|---|---|
| R1. Replay надсилає дубль, бо приймач неідемпотентний (assumed) | 3 | 3 | 9 | replay лише вручну; рядок видаляється одразу після 2xx; приймач отримує `id` задачі для дедуплікації |
| R2. Помилка запису outbox (диск, права) ламає `POST /tasks` | 1 | 4 | 4 | `OSError` перехоплюється, `result="lost"` у метриці, 201 зберігається |
| R3. Паралельні fallback пишуть в outbox одночасно | 2 | 3 | 6 | блокування процесу на append; кожен рядок записується одним `write` |
| R4. Outbox росте необмежено під час довгої відмови | 2 | 2 | 4 | алерт `NotifierFallbackRatio`; розмір файлу видно через `pending` |
| **Разом** | | | **23** | з 100 можливих (4 ризики × 25): клас **Medium** |

Шкала класів: Low ≤ 15, Medium 16–40, High > 40 або будь-який ризик з I = 5.

## План відкату

1. **Тригер.** `POST /tasks` дає 5xx понад SLO, або replay шкодить: дублі, помилки.
2. Зупинити API і повернути код попереднього стану: `git checkout 4041c7a -- tasks/notifier_resilient.py && git rm --cached tasks/notifier_outbox.py`. У релізі це відповідає `git checkout <попередній тег>`.
3. Перезапустити й виконати health-перевірку ([[architecture/isd#isd-deploy]]).
4. Файл `NOTIFIER_OUTBOX` не видаляти. Він інертний і зберігає недоставлені нотифікації для пізнішої доставки. Відновлення даних не потрібне, бо міграцій немає.
5. Час відкату ≈ час розгортання (health 200 за 3 проби, `deploy_drill.txt`).
