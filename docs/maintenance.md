## Правило «зміна коду = зміна документації»

Коміт, що змінює поведінку, видиму назовні, оновлює документацію в тому самому коміті.

| Зміна в коді | Що оновити |
|---|---|
| новий, змінений або видалений маршрут у `tasks/api.py`; формат відповіді | README (таблиця API), SDD §5, за потреби SDD §2-3 |
| новий модуль або компонент, нова залежність між компонентами | SDD §2 (C4) і §3 |
| нова змінна оточення (`os.getenv`) | ISD §3 і `.env.example` |
| порт, процес, compose-сервіс, CI-крок, хук | ISD §1, §5 або §6 |
| зміна моделі даних або формату файлів | SDD §4, ISD §4 (бекап) |
| відмова від рішення ADR | новий ADR зі статусом «Замінює ADR-000N» |

Перевірка:
- запустити `python scripts/doc_audit.py` перед комітом;
- exit code 1 означає, що маршрут або змінну оточення не задокументовано, або живий документ відстав від `tasks/` більш ніж на 20 комітів;
- автоматичного блокування в хуку чи CI поки немає. Чи додавати його, вирішує власник, і це потребує підтвердження студента.
